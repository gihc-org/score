# Session 2026-05-12

## Hvad blev lavet

### Ny applikation: er-det-noget-værd
Bygget en Trustpilot-lignende anmeldelsesservice til venner, hostet på `er-det-noget-vaerd.apps.gihc.online`. Login-flowet matcher `../ipfs-apps` (Argon2id, JWT HS256, Cloudflare Turnstile, email-verifikation via Resend).

**Anmeldelser har:** titel, beskrivelse (emoji-støtte), valgfrit link, rating 1–5.

### Backend (Rust + Axum)
- `src/auth.rs` — Argon2id, JWT, `authenticate`-helper
- `src/routes/auth.rs` — register, login, me, slet konto, email-verifikation
- `src/routes/reviews.rs` — list, opret, slet anmeldelse
- `src/models.rs` — `User`, `Review`, `ReviewWithAuthor`, `CreateReview`
- `migrations/0001_initial.sql` — `users`- og `reviews`-tabeller
- 5 unit tests i `auth.rs` — alle grønne

### Frontend (Vanilla JS + IPFS)
- `index.html` — login/register
- `reviews.html` — anmeldelsesoversigt, stjernevælger, opret/slet
- `style.css` — dark theme, stjerne-UI
- `config.js` / `config.local.js` — prod- og lokal konfiguration

### Infrastruktur
- `Dockerfile` — non-root bruger (CIS-compliant)
- `docker-compose.yml` + `docker-compose.prod.yml` — prod med score-test og score-beta
- `ansible/` — fuld deploy-opsætning (test → smoke test → beta → smoke test → prod → OWASP ZAP)
- `scripts/smoke-test.sh` — tester auth + reviews-endpoints

## Fejl og løsninger undervejs

### Manglende A-records for frontend-domæner
Ansible oprettede kun A-records for API-subdomæner, ikke for `er-det-noget-vaerd.apps` m.fl. Tilføjet til deploy-test.yml.

### Lokal router-cache (NXDOMAIN)
Routeren havde cachet et negativt DNS-svar fra før A-recordsne eksisterede. Løst ved genstart af router.

### TLS-certifikat fejlede ved første deploy
Caddy forsøgte ACME-challenge før DNS var propageret hos Let's Encrypt. Løst ved genstart af Caddy (automatisk retry). Fremadrettet fikset i Ansible med DNS-propagerings-vent før `caddy reload`.

### Dobbelt `/v1` i frontend
`API_URL` i `config.js.j2` inkluderede allerede `/v1`, men frontend-koden tilføjede det igen. Løst ved at fjerne `/v1` fra alle fetch-kald og opdatere `config.local.js`.

### Browser-cache
Efter fix af dobbelt `/v1` virkede det ikke straks — browseren kørte gammel `config.js`. Løst med hard refresh.

## Nye guidelines
